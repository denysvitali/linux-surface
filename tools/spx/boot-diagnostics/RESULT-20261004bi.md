# BI live: user-confirmed touch, pen, keyboard and Bluetooth

`7.3.0-rc2-spx-mainline-20261004bg+` with `spx_attempt=20261004bi`.

The one-shot selection was consumed; `spx-known-good` remains the default.
The user confirms: “Pen works, touch works, keyboard works. BT works”, and reports
that speakers do not work. These observations are attributed to this BI boot.

(`4262fecc320c`), plus the exact-device udev startup rule (`8d3640afc444`).

experimental forwarding path. Never reload MSM.

SPI-HID is ready with zero bus errors. `iptsd@dev-hidraw10.service` started
automatically, connected to `045E:0C21`, and remains active with zero restarts.
The subsequent user report confirms useful physical touch and pen input.
The user's earlier usable-but-low-sensitivity touch result belongs to recovery
f309dbfa/6.18.3. Detailed pen features, multi-touch and resume are untested. This kernel
does not expose tracefs, so the planned metadata tracepoint counts are unavailable;
virtual input-event counts and SPI-HID counters are used instead.
The 60-second observation had no virtual events or IRQ movement, with no
confirmed physical stimulus. All recorded error counters stayed zero.

BI deliberately blacklists WCD/WSA/SoundWire audio drivers. Kernel logs confirm
the blocks and ALSA exposes only the ThinkPad Thunderbolt 4 Dock USB card.
Speaker silence is expected in this configuration; enabled internal playback
remains untested. The next audio step must adapt the known 6.18 stereo sequence,
including late initialization, before an explicitly authorized listening run.

Automatic checks passed RFCOMM socket and UHID opens. Bluetooth has its configured
address and is powered on. Wi-Fi downloaded 25 MB over 5 GHz in 0.528 seconds
(about 379 Mbit/s). ADSP/CDSP/modem report running. No kernel oops, warning trace
or remoteproc crash was found in the collected startup journal. Pairing, peripheral
use and broader lifecycle acceptance remain untested.
