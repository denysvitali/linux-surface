# CN: accelerometer and gyroscope deliver real samples

Boot `32087f09-20e6-4d8f-84a0-21b64e3d5ee5`, kernel
`7.3.0-rc2-spx-mainline-20261004bg+`.

**Changed:** the prepared CL fix supplies a private16MiB SDSP DMA pool, named
HLOS3/SSC_Q6 5 permissions and an invocation-address guard. Firmware reservation
stays separate. Retained Image/module baseline plus rebuilt FastRPC only.
No battery, sound, microphone or camera test.

**Observed:** SLPI starts at27.355s. CMA allocates the shared pool at
`0xfd800000..0xfe7fffff`; FastRPC assigns it successfully to both VMIDs.
The bounded SensorsPD daemon attaches at193.598s with INITpd2, header
DMA`0xfd800000`,4096bytes, inside the assigned heap. Firmware reads saved SPX
sensor configuration. Accelerometer and gyroscope each run for5s at requested
26Hz:120 and119 finite XYZ samples, both clients exit0 and disable their sensors.
Settled accelerometer magnitude is about10.00m/s²; gyro values settle near zero.
SLPI stays running. The daemon stops after both reads; no surviving test process.

**Meaning:** S02a live motion streams pass. The shared DMA pool fixes the missing
prerequisite exposed by CK. This does not establish axis/mount mapping, gyro
units, real rotation changes, automatic desktop rotation, persistence or resume.
The CLI prints a questionable mount matrix and gyro unit label; keep those open.

The installed udev rule omitted `ssc-accel`. Adding that tag to the exact secure
SDSP device makes proxy discovery succeed live, without another attachment.
A bounded12s root `monitor-sensor --accel` receives `bottom-up` orientation and
`tilted-up`; libssc metadata identifies `lsm6dso`. Firmware mount matrix is zero,
so libssc uses identity. No physical rotation or ordinary seated GNOME claim was
verified; remote unseated claims remain denied by normal policy. Proxy remains
available; all bounded clients ended. SLPI still runs.
