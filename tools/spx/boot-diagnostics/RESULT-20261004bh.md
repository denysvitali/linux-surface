# BH: usable keyboard/touchpad; Bluetooth profiles available

Tests completed on boot `c89ea4ed-9363-4727-a786-4a2231817165`, kernel
`7.3.0-rc2-spx-mainline-20261004bg+`. The fixed build adds RFCOMM, HIDP and
UHID modules. The coordinator collected logs and invoked the reusable return
at 836 seconds, before the 900-second fallback. Normal shutdown returned to
known-good `6.18.3-1-surface+`, boot `f309dbfa-4e99-4bdd-9059-efc12f21b817`.
Recovery payloads/default are intact, with no pending boot selection. BH's
timers are disabled; only the current candidate and known-good are retained.

The user reports: “Typed and clicked / used the trackpad. It works”. This
demonstrates basic keyboard and touchpad use (I04/I05). Modifiers, gestures,
detach/reattach and post-resume operation have not all been confirmed.

Automatic checks loaded all three Bluetooth modules, opened an RFCOMM socket
and `/dev/uhid`. After clearing the Bluetooth software block, a first scan
raced firmware setup (`Busy`/`NotReady`); a retry with the controller ready
found 19 nearby devices in 15 seconds and stopped discovery successfully.
Wi-Fi remained connected. Firmware setup logged malformed MSFT vendor events;
the successful scan added no kernel/Bluetooth-service errors. Owned-device
pairing, peripheral use and resume remain untested. Wi-Fi on 5 GHz transferred 25 MB
over IPv4 in 0.825 seconds (about 242 Mbit/s). No reconnect or IPv6 test ran.

AC is online, battery 46% and not charging. Temperatures read 34.3–40.3°C;
ADSP/CDSP/modem report running. APDS9960 proximity reads zero. Charging
transitions and sensor response remain untested.

Eight CPU workers plus FD680 rendering ran together for 180 seconds after
15 seconds idle, followed by 60 seconds recovery. Peak temperature was 60.1°C,
falling to a hottest-sensor reading of 39.5°C at the end. GPU temperature rose
to 47.3°C and recovered to 37.2°C; glmark2 completed at 1427 FPS. No fresh
kernel fault or remoteproc state change occurred. Cooling states remained
zero, so P05 thermal mitigation and B04 service/resume acceptance stay open.

Evidence: `/var/lib/spx-boot-diagnostics/functional/20261004bh/functional.json`,
`bluetooth-test.log` and `thermal-test/` in the same directory, plus the user's
observation in this session. No sound or camera/microphone capture ran. No
complete acceptance box closes. Next are remaining physical input tests,
owned-device pairing and controlled resume.

Later [physical follow-up](PHYSICAL-FOLLOWUP-20261004.md) reports working cover
