# AM distinct-release lifecycle trial plan, 2026-10-01

Build AM from the verified AL/AK source baseline plus the SPI-HID worker/publisher,
output ownership and shutdown callback candidates. Only LOCALVERSION changes in
config. Preserve source/config, modules, kernel, exact corrected DTB, private logged
initramfs and checksums. Offline building and archiving select no boot. Deployment
must first resolve /boot capacity by copying and hash-verifying any inactive slot,
proving no active GRUB/attempt/recovery references, and protecting recovery/active
AE/AG/AI/AJ/AK artifacts. No slot is approved merely by this plan.

First prospective AM trial uses the AK right pin2 reference, native force/core
and watchdog0, bounded enumeration/command diagnostics (16 records,2 dumps),
touch8 windows x48 events, unchanged620s scoped criteria and900s userspace fallback.
Use the existing strict diagnostics implementation; do not relax touch readiness,
DT match, enumeration, graphics/Wi-Fi or error checks. Keep known-good persistent
default, select the new image only once after fresh boot-ID/pending-selection and
recovery/payload/runtime/module hash checks. No manual PCM/audio/input event tests.

The first AM boot comes from known-good, which does not have this candidate
callback. Its incoming result cannot attribute touch startup to candidate outgoing
quiesce. Collect that actual result before deciding any next experiment. If AM
fails, allow900s fallback, verify actual known-good return, preserve logs and
reassess; do not blindly re-arm AM or queue a same-artifact follow-up.

Only after AM passes and fresh review may AN reuse the exact AM release/payloads,
source/config/selectors with just an attempt-marker change for a direct AM->AN
handoff. This is a proposed conditional experiment, not a queued second boot.
Archive actual AM outgoing state before reboot and bind retained pstore/console
shutdown markers to its release/attempt/boot ID before interpreting AN startup.
Journald and userspace collectors can stop before device_shutdown; journal absence
cannot prove callback absence, and pre-reboot collectors cannot prove execution.
Existing collectors preserve /sys/fs/pstore and /var/lib/systemd/pstore. Real late
shutdown marker retention remains unvalidated. Missing markers leave the outgoing
execution/persistence checkpoint unverified. Complete means software teardown
returned, not electrical rail-off. One pair does not establish causality or
reliability. Preserve failed regulator messages too.

Repeated experimental boots including manual power-cycle risk are already
explicitly authorized. EFI/early-kernel automatic recovery is still unvalidated;
userspace fallback is not that proof. Do not unbind/rebind live MSM display devices.
