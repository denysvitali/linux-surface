## Narrow source correction identified

Local comparison against the known-good 6.18 source found a missing A680 GBIF
configuration entry following commit
`60a4e18e0e8ab27d7dfd1316eab31706176481e9`
("drm/msm/adreno: Do CX GBIF config before GMU start"). That commit moved the
four `REG_A6XX_GBIF_QSB_SIDE0` through `SIDE3` writes, each `0x00071620`, from
the GPU initialization function into catalog-driven GMU initialization.

A680 (`0x06080001`) belongs to `ADRENO_6XX_GEN2`, which the old
`adreno_is_a640_family()` condition covered. Its catalog entry did not gain
`.gbif_cx = a640_gbif`; consequently the new loop skipped those four writes.
Relevant source locations are the A680 entry near line 1093 of
`drivers/gpu/drm/msm/adreno/a6xx_catalog.c`, the family helper near line 538 of
`adreno_gpu.h`, and the catalog write loop near line 1032 of `a6xx_gmu.c` in
the same directory. The comparable 6.18 writes begin near line 1238 of
`a6xx_gpu.c` in `../linux-surface-kernel/`.

The missing initialization is a concrete source regression. Its responsibility
for these GMU hangs is still unvalidated. The next trial, `20260922d`, is being
built with only the A680 `.gbif_cx = a640_gbif` correction as its functional
kernel change, under the distinct release
`7.3.0-rc2-spx-mainline-20260922d+`. It retains C's graphical target and GPU
override guard. The staged CMAC option is excluded to preserve this comparison.
Archive and verify the new complete payload before selecting it once; no live
MSM unbind or rebind is needed.
