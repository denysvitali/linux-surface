# Trial 20261008fa: front removed from the graph, IR and rear enabled

Trial boot `b1da04a0`, kernel `7.3.0-rc2-spx-mainline-20261004bg+`. Return to
known-good: see the line at the end of this page.

**Changed:** DTB `ebbc916b7455`. `camera@36` (front OV5693) disabled, and its
CSIPHY0 port and endpoint removed. `camera@60` (IR OV7251) and `camera@10`
(rear OV13858) enabled.

**Observed:**
- Media graph: `ov13858 4-0010` -> `msm_csiphy2` and `ov7251 4-0060` ->
  `msm_csiphy3`, both ENABLED. Before this trial, neither link existed.
- Front: "sensor is not in the camss graph", as expected for a disabled node.
- Test-pattern frames carry the full path (sensor -> CSIPHY -> CSID -> VFE ->
  IOMMU): rear 16-255, mean 135, stddev 119.5; IR 0-255, mean 127.5, stddev
  127.5.
- Scene frames are flat and dark. Rear raw: mean 16, values 15-20. IR raw: mean
  4, values 2-6. Rear processed libcamera frame: mean 39, values 35-60.
- libcamera lists one camera, the rear (`camera@10`), and captures 20 frames.
  It does not list the IR sensor, and it logs "recommended V4L2 control not
  supported" for `ov7251`.
- `camera/result.json` is incomplete because the scene frames fail the
  acceptance test. Front and IR captures ran without kernel errors.

**Meaning:** H-async is confirmed. A disabled front sensor with a CSIPHY0
endpoint keeps camss from linking any sensor. With that endpoint gone, rear and
IR both link and stream. The front bus-1 identify failure (ew/ex) is still
unexplained, but it no longer blocks the other sensors.

The flat dark scene is a separate question. Both sensors produce it, so the
cause is probably the scene (lens covered, unlit, or a dark surface) or exposure,
not the link. The 6.18 rear frames had a real scene. This trial does not decide
between these.

**Refuted:** front bus-1 pins as the reason the graph fails (ex), and the
front-only failure as the reason the rear never linked.

**Next:** confirm the physical scene with the user (lens uncovered, room lit,
camera pointed at a scene). Then check whether the IR OV7251 needs a libcamera
pipeline entry, and separately continue the front OV5693 identify failure.

**Return:** automatic at 900 s. Known-good `6.18.3-1-surface+`, boot `cd295400`;
persistent default `spx-known-good`, next entry empty, known-good payloads intact.
