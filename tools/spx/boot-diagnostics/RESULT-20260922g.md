# SPX isolated QRTR rollback — result, 2026-09-22

Trial `20260922g` completed a 756.96-second observation with one modem start
and no service-announcement failure or modem fatal error. Wi-Fi activation completed about
43.5 seconds earlier than in F. Hardware EGL rendering, automatic IPTSD
startup and the guarded audio stage-1 handshake also succeeded.

The planned 600-second window completed, and the final collector snapshot is
at 757.24 seconds. Evidence was archived and hash-verified before the fallback
was stopped and mainline retained. **No recovery reboot was performed.** This
single clean boot supports the QRTR hypothesis within its stated limits; it
does not prove the intermittent race resolved. Physical touch/pen and audio
playback remain unverified.

G's ath10k QMI initialization followed the first modem start by 0.713 seconds;
F's followed the recovered modem start by 0.806 seconds. NetworkManager
activation was 43.524 seconds earlier in G. This is consistent with avoiding
F's roughly 40-second failed modem-start interval. It supports the QRTR
handshake hypothesis, but does not prove the failed send's errno or the
firmware's internal failure cause. Earlier E also completed a clean baseline
with the original QRTR code, so a single clean G boot does not settle an
intermittent race.

No service-announcement failure or modem fatal error was found through
756.96 seconds. The final collector reports modem, ADSP and CDSP all running, with
Wi-Fi connected through NetworkManager/wpa_supplicant. Cellular connection
and sustained Wi-Fi transfer remain untested. Iwd still logs another-supplicant
and unsupported-scan warnings; the QRTR rollback does not fix that existing
userspace manager overlap.

The rollback removes proactive HELLO behavior needed by some passive MHI
endpoints. G uses QRTR SMD and does not enable QRTR MHI. Treat this as the
device-specific diagnostic comparison described in
[QRTR-20260922.md](QRTR-20260922.md), not a generally validated upstream fix.

## Separate cellular control checks

After the baseline, QRTR discovery and two read-only QMI GETs succeeded at
783.46–783.57 seconds. DMS reported operating mode `factory-test`, with no
hardware restriction. UIM reported slot 1's card absent. The commands changed
no operating mode, SIM unlock state or data session.

`cellular-control/` in the attempt archive preserves command/timing metadata,
discovery and response logs, and `result.json`; all four files listed in its
`SHA256SUMS` were verified. Discovery includes an IPA control service, but
there is still no WWAN/IPA/RMNET host data path. Successful modem control
queries therefore do not establish cellular data connectivity, and the absent
card is a separate limitation.
