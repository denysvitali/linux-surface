## Framebuffer correction

The warning at the console takeover belongs to MSM: `sys_imageblit` reports
that the framebuffer is not in virtual address space immediately before
`msmdrmfb` registers. `sys_fillrect` issues the equivalent warning later.
Simpledrm registered earlier without these warnings.

`msm_gem_get_vaddr()` maps the backing pages with `vmap()`, and MSM uses
`FB_GEN_DEFAULT_DEFERRED_SYSMEM_OPS`. Set `FBINFO_VIRTFB` after successfully
obtaining `screen_buffer`, preserving the other `fb_info` flags. This matches
the memory type required by those helpers and the existing DRM shmem fbdev
implementation. It applies to both stolen and regular buffer allocations.

The helpers warn and then draw even when the flag is absent. This change
corrects the metadata and warning condition; it is not a demonstrated fix for
the freeze, GPU rendering, or the previously observed live DPU unbind fault.
No new hardware experiment is justified by it.
