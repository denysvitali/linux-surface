## Why the GBIF change matters

Commit `60a4e18e0e8ab27d7dfd1316eab31706176481e9` moved four
`REG_A6XX_GBIF_QSB_SIDE*` initializations into the catalog-driven GMU start path.
The earlier family condition covered A680, but its catalog entry omitted the
new pointer. D restores those four `0x00071620` values through the existing
`a640_gbif` table. The source omission and successful C-to-D comparison support
retaining the correction. Repeated and longer runtime validation remains useful.

## SMEM and UBWC result

`smem-hbb` contains the preserved read error
`cat: /sys/kernel/debug/qcom_smem/hbb: Invalid argument`, rather than a numeric
HBB. `smem-dram-frequencies` successfully records eleven frequencies ranging
from 200 MHz to 2092.8 MHz.

The HBB interpretation follows the local code: `smem_hbb_show()` in
[smem_dramc.c](../../../drivers/soc/qcom/smem_dramc.c) returns `-EINVAL` when
the cached HBB is zero. `qcom_smem_dram_get_hbb()` returns `-ENODATA` for that
condition. `qcom_ubwc_config_get_data()` in
[ubwc_config.c](../../../drivers/soc/qcom/ubwc_config.c) then retains the
SC8180x platform fallback, `ubwc_3_1_hbb16`. Thus D used the existing HBB 16
fallback; this is a source-based inference from the captured read error,
not a numeric firmware HBB measurement. The successful trial gives no reason
to change UBWC as part of the next experiment.

## Remaining failures and continuation

- `iwd.service` still fails because CMAC support is absent. NetworkManager
  nevertheless connected through `wpa_supplicant`: WPA/CCMP key negotiation
  completed at 118.174 seconds, DHCP assigned an IPv4 address at 119.028
  seconds, and NetworkManager reported activation at 119.071 seconds. The
  recorded disconnection was local and occurred during shutdown. This passes
  association and DHCP through that backend; no sustained transfer test was
  performed.
- `spx-audio-modules.service` still fails with no soundcard. SLIMbus remains at
  its stage-0 guard.
- `iptsd@dev-hidraw4.service` fails while opening the correct SPI touchscreen
  (`045E:0C21`): the kernel reports zero input headers, then a firmware-ready
  timeout at 29.408 seconds. The current 6.18 recovery boot connected the same
  daemon to the same device and created virtual touchscreen/stylus nodes.
  Independently, D's extracted config lacks `CONFIG_INPUT_UINPUT`, whereas
  recovery enables it as a module. C previously completed the SPI transport
  open at 22.515 seconds, then iptsd failed opening `/dev/uinput` at 22.524
  seconds. Enabling `CONFIG_INPUT_UINPUT=m` in a future build is a confirmed
  prerequisite for the daemon's virtual devices; it does not resolve D's
  transport timeout. D's touch/pen operation remains unvalidated.
- The modem crashed and recovered at approximately 68.28 and 108.87 seconds.
  A final `running` snapshot does not establish modem stability.
- External DisplayPort, speakers, cameras and suspend/resume are not passed by
  this graphical startup result.

The next planned trial E enables only `CONFIG_CRYPTO_CMAC` plus a distinct
release, preserving the GBIF fix and C/D GPU policy. A 600-second return window
is planned for longer graphical and diagnostic validation. That longer run and
the CMAC change have not yet been tested on hardware.

CMAC restores an iwd startup prerequisite; it is not required for the observed
NetworkManager/wpa_supplicant association. A read-only check of the recovery
boot found NetworkManager, iwd and wpa_supplicant all active, with the default
NetworkManager `wifi.backend=wpa_supplicant` and no iwd backend override. Iwd
reported the station disconnected while NetworkManager had connected it, and
its journal showed autoconnect attempts. Thus starting iwd in E restores an
existing overlap between Wi-Fi managers that should be checked for contention;
it does not itself change NetworkManager's backend.

Automatic agent continuation remains unresolved: D's recovery helper attempted
remote-mode startup without `HAPPY_RPC_TOKEN` and failed. The service evidence
is archived, and the user manually continued the session. The kernel's
automatic return succeeded independently of this agent-resumption failure.
