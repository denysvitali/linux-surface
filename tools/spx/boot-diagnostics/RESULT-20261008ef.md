# EF: demosaiced view of the EV bright frame (C02/C03 evidence, analysis only)

Same capture as `20261008ev`; no boot and no kernel change. The raw 8-MSB view
is grayscale because `camera.py` writes the high bytes of SGRBG10 without
demosaicing, and it appears upside down because the board DT sets
`orientation = <1>` on the rear sensor.

**Change:** offline conversion of
`/var/lib/spx-boot-diagnostics/functional/20261008ev/camera/frames-bright.raw`
to a 2112x1568 Bayer image (every 5th LSB-pair byte lifted out), demosaiced as
`bayer_grbg8`, then flipped both ways. Bayer plane means: R 35.4, G 36.7 and
36.9, B 27.2 — real colour data, not a grey image relabelled.

**Observed:** a real scene — a person lit by a laptop's glow in a dark room
with a bright ceiling strip behind. Upside down, matching `orientation = <1>`.
This is the camera that faces the user, so it is the front camera path even
though the board node calls it `camera@10` / rear.

**Meaning:** the bright frame is genuine scene data, and the earlier reading
of the same frame as "no real scene" was wrong. The camera path is confirmed
end to end. What is left for C02/C03 is orientation (this is upside down) and
repeated stream start/stop plus resume. No box changes; C01 stays open until
those are done and a person confirms the picture.
