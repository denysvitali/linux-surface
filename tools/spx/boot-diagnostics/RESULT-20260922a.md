# SPX mainline text-target result — 2026-09-22

Trial `20260922a` reached multi-user mode, remained responsive to the bounded
collector, and returned through an orderly shutdown to known-good 6.18. This
is a successful three-minute text-target trial, not a completed hardware port
or a graphical-session pass. The earlier loss of logs around 27–29 seconds
was not reproduced with this payload and target.

## Observed result

The journal records `msmdrmfb` creation at 11.380 seconds and multi-user
target at 36.466 seconds. The return service started at 180.151 seconds;
the final collection's uptime is 180.22 seconds. Shutdown continued through
the journal's stop at 194.097 seconds. This identifies a planned userspace
return, rather than an unexplained disappearance of the trial journal.

The APSS `qcom_wdt` was opened by initramfs and host systemd with a 30-second
timeout. The trial did not exercise watchdog expiry or establish automatic
recovery across ExitBootServices. At shutdown, systemd twice requested an
unsupported ten-minute watchdog timeout; those warnings did not prevent the
recorded shutdown and recovery boot.

No oops, panic, GPU fault, or `sys_imageblit`/`sys_fillrect` virtual-address
warning was found in the complete trial journal. The MSM framebuffer flag
change removes the earlier warning on this observed boot. Because the payload
and userspace target differ from the preceding trials, it does not by itself
explain their freezes.

| External DisplayPort | Primary DP controller bound, but connector disconnected. `spx_hpd_inject` is missing for this kernel. No external display pass. |
| Wi-Fi | `iwd.service` failed with `No CMAC(AES) support found`; `CONFIG_CRYPTO_CMAC` is unset in the trial. AES and the userspace hash API are enabled. The separately missing `CONFIG_KEY_DH_OPERATIONS` disables WPS. |
| Audio | No soundcard; `spx-audio-modules.service` failed. The local SLIMbus driver explicitly stopped before QMI mutation because `spx_probe_stage=0`. This guarded configuration does not establish audio support. |
| Modem | Fatal errors at approximately 67.0, 107.6 and 148.2 seconds, each followed by recovery. Another occurred at 188.8 seconds during shutdown. The final `running` snapshot does not establish modem stability. |
| ADSP/CDSP | Both were running in the final snapshot. An APR wrong-header warning remains. |
| SPI HID | Invalid `0xff`/`0x00` report headers and a firmware-ready timeout occurred. SPI HID header errors and the APR warning also appear on the known-good recovery kernel, so they are not established 7.3 regressions. |
| Storage/USB | NVMe and USB enumeration survived the bounded trial. No storage or USB stress test was performed. |

The kernel `qcom_pd_mapper` module and userspace `pd-mapper.service` were both
active; investigate their interaction when addressing the modem/QRTR errors.
This is a lead, not an established cause.

The confirmed iwd prerequisite is now recorded as `CONFIG_CRYPTO_CMAC=m` in
`arch/arm64/configs/spx.config` for a later build. The active `.config` and
trial artifacts were not changed. Applying the fragment requires rebuilding
the kernel as well as modules: `crypto/aes.c` conditionally compiles the
`cmac(aes)` implementation, and AES is built into this trial kernel.

## Continuation

The next narrow comparison is the same kernel, modules, DTB and initramfs
with `systemd.unit=graphical.target`, retaining the bounded return and logging.
Use a new attempt identity and a one-shot selection; collect its result before
choosing another experiment. Do not unbind or rebind live MSM components.

Automatic agent continuation did not work on this return: the installed Happy
Codex path ignored the scheduled loop. The user's manual `Continue` resumed
the work. The previous resume helper has been disabled. A completed kernel
return must not be confused with a working agent-resumption mechanism.
