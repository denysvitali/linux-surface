# CT: automatic firmware TPM startup works

Boot `b56c1e85-0913-4327-aade-233064c8b45a`, kernel
`7.3.0-rc2-spx-mainline-20261004bg+`, Image build #13.

**Changed:** add the preloaded `qcom.tz.tpm` application to the existing
QSEECOM auxiliary registry and enable the guarded legacy TPM module. The fixed
build config adds only `CONFIG_TCG_QCOM_QSEE=m`. Prepare matching modules on
CS; return to known-good before replacing that module tree and selecting CT
once. The reusable harness now permits this recovery installation transition.
The sensor/USB-C setup and CS DTB are retained; codecs remain blacklisted.

**B06b passes:** boot discovers the TPM application at 2.49s. Normal driver
loading creates `/dev/tpm0` and `/dev/tpmrm0`, with no `spx_tpm_lookup` module.
Two independent bounded clients exit0: TPM2.0/QCOM properties, active
SHA1/SHA256/SHA384 banks, nonzero SHA256 PCR0 and distinct nonzero 32-byte
random responses. PCR0 and update counter91 remain unchanged across opens.
No Clear, provisioning, persistent keys or PCR writes are performed.

**Baseline:** automatic checks complete on this boot; 25 MB Wi-Fi transfer
passes. Both CPU policies switch to schedutil. Sensor provider708/proxy1270
remain running with zero restarts. The native active UID1000 client claims
the accelerometer and receives `bottom-up`/`tilted-up` under existing polkit
policy. A separate sudo/runuser context is denied as expected; no policy
relaxation is made. Physical rotation remains unresolved. No new kernel
oops is found; the already parked Venus probe still times out.

**Meaning/next:** ordinary fitted TPM access works on mainline. Full B06
still needs signing/Secure Boot and resume. The subsequent read-only
[measurement replay](RESULT-20261006ct-measured-boot.md) closes B06c.
`tpm2.target` remains masked for the known-good kernel without a TPM driver.
Preserve firmware ownership and recovery; do not enroll keys implicitly.

Evidence: `/var/lib/spx-boot-diagnostics/functional/20261006ct/`, baseline
`functional.json` and `tpm/{startup,check-result,reopen-result}.json`, kernel
and active-user motion logs. Known-good is the persistent default; CT has
the existing 900s automatic return.
