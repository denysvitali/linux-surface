# CF: connected charger increases battery energy on mainline

Boot `c36de673-14e4-4c2f-bb90-5a41fc1a37b9`, kernel
`7.3.0-rc2-spx-mainline-20261004bg+`. **P01a passes:** actual charging on the
connected charger. P01 as a whole remains open.

**Changed:** the user connected AC and requested continuation. CF reuses CE's
kernel and corrected TCS3430 DTB, with the same non-audio USB-C configuration.
No new kernel change, sound, microphone/camera capture or suspend occurred.
Known-good stays the default; the trial is selected once with automatic return.

**Observed:** 25 numeric samples over 120.035 seconds show AC online and
Charging throughout. Battery energy rises 8.17→9.43 Wh (+1.26 Wh), capacity
27→31%; voltage is 8.298–8.311 V and reported battery power 42.900–42.972 W.
Sampled temperatures span 37.035–43.945°C. No new kernel oops, IOMMU, firmware
or display faults were found. Startup checks completed on this boot. The
device tester released its lock and retained the armed return timer.

**Meaning:** charging produces real energy gain on mainline; this is more than
a status-bit observation. Charger type was not supplied, so the result does
not establish both USB-C and Surface Connect coverage or an AC transition.
BU's earlier 49% Not charging observation still has no proven policy explanation.

**Next:** retain this per-feature pass and return to known-good. P01 still needs
charge-policy, charger/port coverage, transitions, discharge and low-battery
behavior. The P02 idle/load/recovery helper requires mains disconnected and
battery ≥20%; it was not run while charging.

Evidence: `/var/lib/spx-boot-diagnostics/functional/20261005cf/charging/`
contains `result.json` and starting/final/new kernel logs. Trial kernel/journal
capture and return evidence are retained in the parent directory.
