# B05: missing kernel RTC synchronization path

AW's collected result and verified return preceded this investigation. Current
known-good boot `fbc6d663-8269-4d2f-9aac-c4a687583b00` runs
`6.18.3-1-surface+`; no trial is selected. Its RTC0 is the SSAM
`surface_rtc 01:01:01:00:00`, not a PMIC RTC. RTC0 reports hctosys1 and the
kernel journal records setting system time from it. Chrony then steps startup
system time by-791.754695s. `/etc/adjtime` uses UTC; this is not a two-hour
local-time offset.

[Read-only observer](observe-rtc-sync.py) makes two RTC_RD_TIME ioctls, separated
by15s, bracketed by realtime and monotonic reads. At1695.29/1710.29s uptime,
the conservative RTC-minus-system intervals are790.355–791.357s and
790.352–791.354s. Chrony tracking reports leap status Normal/stratum2 and
timedatectl reports system synchronized. This confirms that the offset persists
well beyond an11-minute interval; two short samples do not establish drift.
No observer RTC/system write, NTP policy change or network disconnect occurred.

Both the running known-good embedded config and the AU mainline candidate have
`CONFIG_RTC_SYSTOHC` disabled; neither enables `CONFIG_GENERIC_CMOS_UPDATE`.
The effective chrony configuration explicitly enables `rtcsync`.
[Chrony4.8 documentation](https://chrony-project.org/doc/4.8/chrony.conf.html#rtcsync)
specifies that Linux delegates this copy to the kernel. Local
`kernel/time/ntp.c` compiles its synchronization worker only when one of those
two options is enabled; its RTC fallback requires `CONFIG_RTC_SYSTOHC`, opens
`CONFIG_RTC_SYSTOHC_DEVICE`, and calls rtc_set_time only with synchronized NTP
status. `drivers/rtc/rtc-surface.c` supplies set_time through the SSAM RTC command.
Thus the configuration currently prevents the intended synchronization path.
This explains failure to correct an existing offset, not its original cause or
any long-term hardware drift.

The board fragment now explicitly selects `CONFIG_RTC_SYSTOHC=y` and
`CONFIG_RTC_SYSTOHC_DEVICE="rtc0"`. A distinct AX candidate uses the frozen AU
source and a private clone of AU's output tree. Normal native Kbuild must run
Image/DTB/modules and modpost with the new configuration; old objects may be
reused only through its dependency checks. Effective configuration must differ
from AU by exactly RTC_SYSTOHC, RTC_SYSTOHC_DEVICE and the distinct AX release.
No C driver change, guessed RTC offset adjustment or manual RTC write is proposed.
The live board fragment is an explicit configuration overlay; it is separately
archived and does not silently rewrite the frozen AU source archive.

Before hardware trial: verify embedded configuration, RTC synchronization code,
193 matching modules, exact AT rear/LED DTB/private initramfs, source/archive and
parent-output hashes, known-good recovery/default and one-shot guard. The trial
must record RTC/system/NTP status over startup and at least one subsequent
11-minute interval, with existing startup/baseline/camera regressions and a
guarded known-good return. Record success or failure from actual RTC readback;
a build/config change is not proof that the write works. Ftrace is disabled in
the current configuration, so no RTC tracepoint observation is claimed.

After an actual synchronization pass, B05 still requires retention across
power-off and timekeeping across suspend without network corrections concealing
the result. These are separate tests, as are startup/shutdown B01 and full
common-candidate F02/F03. B05 remains open.
