# BN: mainline speaker tones pass automatic microphone verification

Boot `b6ebb51f-0d63-4946-a631-e2ab3f424569`, kernel
`7.3.0-rc2-spx-mainline-20261004bg+`, ran the consumed-once acoustic test at
21:19:34 CEST on 2026-10-04. The change from BM was the WSA late-init fix
`c01151980634`: cycle the actual machine speaker endpoint after the runtime
clock switch. Both native codecs now report one successful late initialization.

At minimum PA gain, the helper played two seconds each of left 440 Hz, right
660 Hz and both together. One continuous internal DMIC1 capture covered quiet,
startup, tones and the amps-off control. `success` and `acoustic_passed` are true.

| Phase | Tone level above quiet at the same frequency | Result |
|---|---|---|
| Left 440 Hz | 16.5 dB | Sustained tone detected |
| Right 660 Hz | 31.2 dB | Sustained tone detected |
| Both | 16.4 / 31.1 dB | Both detected in the same window |
| Same digital tones, amps off | -1.9 / -4.4 dB | Neither detected |

The amps-off control kept playback and capture running, confirming that the
detected tones depend on the powered amplifiers. This closes the narrower
functional checks A01a and A02a. It does not establish physical left/right
placement, stereo balance, calibrated loudness, useful volume range or normal
desktop audio. Full A01/A02/A03 acceptance remains open.

DMIC1 recorded 1,211,520 frames at 48 kHz, S16_LE/mono. Quiet RMS was 6.82 PCM
counts; there were no clipped samples or capture errors. The helper deliberately
terminated its owned capture process, explaining its exit status 1. All six
microphone controls restored successfully. Both amplifier enables were verified
low, playback/capture processes closed and master runtime PM restored to auto.
Closing playback after amplifier powerdown still produced SoundWire FIFO and
DAPM teardown errors; this is the remaining lifecycle problem, not a clean-close
pass. Fix that sequence before claiming reliable normal playback/reopen.

The scheduled return executed at 21:22:03 CEST. `return.json` confirms intact
known-good payloads, persistent `spx-known-good` and an empty one-shot selection.
Recovery boot `fef42d2a-ac47-4af8-9d1d-8c971d514be6` runs `6.18.3-1-surface+`.
This return was planned; the earlier unexplained BL/BM restarts remain unresolved.
Battery was 10% and discharging when results were collected: defer more device
trials until charged. Keep BN as the current candidate.
