# DD: sensor backend survives timed s2idle with FastRPC freezer fix

Actual boot `38f7cb85-f4cf-48a0-af50-42bf1af6b183`, kernel
`7.3.0-rc2-spx-mainline-20261004bg+`; unchanged Image and DC DTB/RTC.

**Problem/change:** DC's interrupted listener was restarted with a duplicate
context, then SensorsPD/SLPI crashed. `91d00ee2efc1` keeps the same invoke across
freezer/thaw using standard freezable completion and recalculates actual signals
under the sighand lock. Kernel timeout/ordinary signals and DMA lease guards
remain. Changed module compiled and installed from known-good recovery;
module bytes match the build. Initial failed modules staging is retained.

accel/gyro/mag yield78/70/29 finite samples with clean disables. A15-second

no new DSP/FastRPC fault or busy ownership lease. S02g closes for one backend
freeze/thaw. Evidence is `sensor-suspend/result.json`, its before/after stream
records, and `pmic-rtc-suspend/result.json` under DD's functional directory.

**Limits:** active application continuity, repeated sleep, physical axes/bearing
and full device recovery remain unverified. This does not close full S02/P03 or
prove recovery from unrelated firmware faults. DA reset failure remains open.
Systemd sleep stays masked. No sound, camera/microphone capture or battery test.
