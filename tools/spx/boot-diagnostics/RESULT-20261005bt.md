# BT: active silence insertion corrupts the waveform

Boot `e2ed1bb6-c5cd-4fe0-bad6-a6c9681cb133`, kernel
`7.3.0-rc2-spx-mainline-20261004bg+`. The public-scoring quiet fix was installed,
but the first temporary left phase failed before reaching that code. Both
native amplifiers initialized successfully; PCM did not underrun. Actual DSP
counters were 228 submitted, 228 WRITE_DONE and zero timer fallback.

The nominal 440 Hz score was 0.94 RMS and not sustained. The saved waveform
instead contains a strong line near **436.9 Hz**, around 1.7–2.04 RMS. The
feeder inserted 47 five-millisecond silence blocks (235 ms) during this first
phase. A synthetic 440 Hz waveform with periodic five-millisecond insertions
reproduces the 436.9 Hz line. Preserving nonzero samples alone did not preserve
their timing: the earlier gap-filling change introduced this defect.

`804b067ef187` removes active silence insertion. Active forwarding waits for
real source frames in health-checked intervals; the PCM buffer absorbs normal
delivery bursts. Idle and scoring still use local silence. The separate
public-scoring fix remains, as it addresses the independently reproduced CPU
contention. Levels, geometry and acoustic thresholds are unchanged.

The replacement test has an independent 48 kHz consumer with a 250 ms ring
and a source that starts empty and alternates 95/145 ms bursts. It checks the
entire contiguous stereo waveform, including zero crossings, and exercises
idle → active → scoring transitions. The fix has zero underruns and preserves
all 95,996 active frames. The previous implementation fails the same test by
adding 1,920 frames. All 28 audio tests pass.

The startup failure parked both amplifiers, closed playback/capture and
restored microphone controls without cleanup errors. Guarded FIFO recovery
passed. The live retry with the replacement again produced no coherent left
tone after reopen. BU will test only this waveform fix at a fresh startup.
No desktop handoff or reliable reopen is claimed; A01a remains reopened.
The public higher-volume path was verified on BS, but remains unavailable for
ordinary applications after this failed startup.

Evidence: `/var/lib/spx-boot-diagnostics/functional/20261005bt/`, including
`audio/serve-result.json`, private capture, full logs and live-repair results.
BS payload/staging/instance links are retired; its evidence remains. BT's
fallback is uptime 3600, with known-good still the persistent default.
