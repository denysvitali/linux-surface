# AR: firmware touch power delay, compiled rear lifecycle driver

Targets I01 and preparation for C01. Latest actual trial AQ failed initial
SPI-HID probe and the strict 620-second baseline; its userspace fallback
returned to known-good boot `991a6fbd-2217-4f93-8185-287a223a13f6`.
AQ will not be re-armed. See RESULT-20261003aq.md and
TOUCH-FIRMWARE-TIMING-20261003.md for actual failure and firmware provenance.

AR freezes the complete current source into a distinct isolated native build,
release `7.3.0-rc2-spx-mainline-20261003ar+`. The DTB retains AQ's provider-only
camera subtree and adds exactly `/ts-5p0-regulator/startup-delay-us = <300000>`.
All other properties, nodes and memory reservations must compare exactly to AQ.
The driver holds digitizer reset while the first regulator enable waits; its
existing post-release wait, IRQ/poll budgets and wire format are retained.
The independent firmware reset method remains outside this property's scope.

The config changes only LOCALVERSION plus CCI, OV13858 and their minimal V4L2
framework dependencies. All previously built modules must remain, with only the
reviewed CCI/rear/framework modules added. This makes the rear lifecycle fix
compile/link against the actual new kernel exports. No CCI, sensor or CAMSS
hardware node will be enabled, and no camera rail consumer is introduced.
The previous 171 fault tests remain offline evidence, not hardware acceptance.

Preparation checks actual known-good boot, empty one-shot selection, persistent
known-good default, EFI files, three recovery payloads and all 5,183 module
files/links. AQ artifacts, failed result, verified return and offline follow-up
manifests are rehashed. The live AM .config and recovery artifacts stay protected.
Complete source/config/kernel/modules/DTB/private initramfs provenance and an
independent archive review are required before deployment or one-shot selection.

Actual AR validation must retain the strict baseline and cold-start chronology,
including initial probe and later opens. Do not restart/reset/rebind live touch
or MSM to conceal failures. Collect the actual result before another candidate;
userspace fallback does not establish EFI/early-kernel automatic recovery.
No hardware acceptance item closes from this build or one successful boot.
