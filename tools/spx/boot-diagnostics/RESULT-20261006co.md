# CO: automatic desktop sensors and live compass

Boot `5c15d575-a56c-4f82-9afb-be6bb1da64de`, kernel
`7.3.0-rc2-spx-mainline-20261004bg+`.

**Changed:** same CN Image/DTB/modules, with opt-in durable SensorsPD startup,
early FastRPC loading, metadata readiness and the scoped `ssc-accel` udev tag.
Proxy dependencies apply only with `spx_sensors=1`. Saved vendor configuration
and private daemon/library are installed; calibration writes remain unsupported.
No battery, speaker, microphone or camera test.

**Observed:** SLPI runs at27.683s; shared heap assignment succeeds. The initial
SensorsPD host attaches at28.942s with DMA inside that heap. Provider becomes
ready at33.531s and proxy starts at33.631s. No manual attach or service restart.
Proxy exposes the accelerometer and `bottom-up` orientation. Two bounded12s
native root clients query orientation/tilt across close/reopen; listener817,
provider733 and proxy1244 remain alive with zero provider restarts.
Fresh3s CLI streams return92 accelerometer,68 gyro and29 magnetometer finite XYZ
samples; all exit0 and explicitly disable. Magnetometer identifies `ak0991x`,
vendor`akm`. A bounded10s native compass client receives changing headings near
89degrees. This measures the API, not bearing accuracy. SLPI remains running.

**Meaning:** S02b automatic desktop backend and S02c live magnetometer/heading
API pass on this boot. Calibration, physical axes/rotation/bearing, ordinary
seated GNOME consumption, repeated startup and resume remain unverified.
The mount-matrix warning is misleading: libssc0.4.4 sums floats into an integer,
then overwrites only the diagonal on fallback. Saved fractional placement values
therefore produce off-diagonal0.1 entries; this can distort motion measurements.
Do not treat current orientation as proof of correct physical mapping.

first host, test userspace changes live and leave physical acceptance open.
