# CH: SLPI memory setup rejected before execution

Boot `20a64235-a249-4fc8-9950-8b38d300dee6`, kernel
`7.3.0-rc2-spx-mainline-20261004bg+`. Same kernel/modules as CG; only SLPI DT
feature added. No physical help, audio, capture or battery tests.

**Changed:** dynamic20MiB/1MiB-aligned SLPI reservation, secure PAS12 node and
Windows-derived GLINK host3/SPI170/mailbox24. IRQ handshakes reuse Q6 family
protocol. No guessed Q6 MMIO or FastRPC context banks.

**Observed:** Linux allocates `0xfd600000..0xfe9fffff` exclusively. At27.565s
SLPI loads `qcslpi8180.mbn`; metadata initialization succeeds, then PAS memory
setup rejects the relocated region with `-22` at27.685s. Failure occurs before
segment copying, authentication/reset or ready IRQ. SLPI remains offline;
modem, ADSP and CDSP run. QRTR has neither SSC400 nor SMGR256. Existing reserved
memory overlap warning also appears on the baseline; it is not the new region.

**Meaning:** relocation and Linux ownership alone do not establish a PAS12
accepted physical range. This did not test IRQ, GLINK or sensor operation.
No S02 acceptance box closes. Do not repeat this allocation unchanged.

**Follow-up:** the documented read-only PIL memory-area query succeeds on this
boot at976.597s and reports `[0x8b700000,0x9ab00000)`. CH's allocation is outside
that pool. Windows `qcpil8180.sys` uses this getter to constrain allocation.
The lower3GiB guess (CI) was canceled before selection or boot.

**Next:** CJ tests a fixed20MiB slot `[0x8be00000,0x8d200000)` inside the reported
pool, without overlap with current DT reservations. This UEFI-reserved slot is
not Linux free RAM. PAS12 acceptance remains unverified. Keep the ELF's original
`0x97300000..0x98700000` region untouched: it overlaps ADSP. Image, installed
modules, firmware and IRQ/GLINK wiring stay unchanged; new USB HPD IRQ code
