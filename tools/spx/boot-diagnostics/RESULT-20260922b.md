# SPX graphical trial: GMU failure — 2026-09-22

Trial `20260922b` started GNOME on the same kernel, modules, DTB and initramfs
that completed [the text-target trial](RESULT-20260922a.md). It then recorded
a GPU frequency-vote timeout, GMU watchdog expiry and GPU recovery failure.
The 180-second return did not complete. This is a failed graphical trial with
an identified GPU/GMU failure path; the underlying cause remains unresolved.

## Interpretation and next comparison

The existing `/etc/systemd/system/gpu-freq.service` forces the userspace
governor. The user's `power-profile-watcher.sh` changes both the system power
profile and GPU frequency; on battery it requests 315 MHz. It wrote the GPU
controls shortly before the fault. The successful text boot started the same
units but recorded no equivalent user frequency write.

The failed HFI message is the frequency/bandwidth vote sent by
`a6xx_hfi_set_freq()` in `drivers/gpu/drm/msm/adreno/a6xx_hfi.c`, called by
`a6xx_gmu_set_freq()`. This makes frequency transitions a useful isolation
target. It does not establish the script as the cause: even an unsupported
userspace frequency request should not hang the kernel. “Offending task”
identifies the GPU workload during failure, not a proven GNOME defect.

The next planned trial, `20260922c`, retains the same artifacts and graphical
target and adds `spx_gpu_profile=skip`. This skips `gpu-freq.service` and guards
only the GPU writes in the watcher/cycle scripts, preserving their
power-profiles-daemon operations. The comparison therefore leaves the GPU
driver's default governor in control without removing the system power-profile
operation. Keep logging and the bounded return; collect the result before
choosing any kernel fix. Do not unbind or rebind live MSM components.

No framebuffer virtual-address warning recurred. `iwd` still reported missing
CMAC support; the board-fragment fix has not been built into these artifacts.
The no-soundcard snapshot and SPI HID/iptsd errors also remain unresolved.
None of these observations establishes a completed audio or input port.

## Agent continuation

The recovery resume helper repeatedly failed to establish or acknowledge the
Happy session state, and the user's manual continuation resumed investigation.
Its separate service log is archived. This agent-resumption problem is distinct
from the GPU failure and does not identify the source of the hardware reset.
