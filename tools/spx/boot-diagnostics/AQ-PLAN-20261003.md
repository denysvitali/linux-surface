# AQ camera-provider trial plan, 2026-10-03

Targets: **C01**, with regression observation for **I02/I03**. This experiment
tests the three measured standard SPMI camera providers before adding consumers.
It does not accept camera capture or full hardware operation.

The isolated build snapshots all96,765 tracked/untracked source records and
keeps the running AP config unchanged. Its distinct release is
`7.3.0-rc2-spx-mainline-20261003aq+`; config differs from AM only in LOCALVERSION,
with the trailing `+` explicitly supplied to Kbuild in the snapshot without git.
It includes the previously reviewed SPI-HID output bounds, rear sensor supply
ordering, CCI binding and measured PMC8180 SPMI provider changes. Sensor drivers
and camera controller nodes remain disabled/absent from the trial configuration.

The base board DTB must reproduce AM byte-for-byte. The boot DTB adds exactly
`/soc@0/spmi@c440000/pmic@1/regulators` and its l1/l14/l17 children. Existing
properties, memory reservations, audio pin2/native enumeration and touch selectors
must remain unchanged. The provider has exact1.200/1.800/2.856V constraints and
the existing board supply-group input phandles, with no consumer, always-on,
boot-on, initial-mode or pin-control request. Source expectations are no voltage/
enable/initialization write when current hardware controls match; that is not
proof of transient electrical state or firmware arbitration.

Before deployment, build the whole kernel and187 modules, stage202 module-tree
files, build/extract the private logged initramfs and verify all54 embedded module
payloads. Preserve the full source archive, source/config, Image/compressed kernel,
DTBs, modules/exports, initramfs and all logs. Independently stream/hash the full
source archive, check the one-subtree DT change and matching module release.
Keep existing AM/AP artifacts and all known-good payloads/modules/entry/EFI intact.

The separate read-only collector runs at60s, verifies actual AQ identity and
reads the three named regulators' voltage/constraints, disabled state, zero users,
provider driver and OF parent. Then21 fixed-record PMIC reads compare identity,
mode and VSET/enable bytes to AP. It archives partial failures. It never requests
enables/voltage, module operations or a camera stream. Registration success is a
bounded finding. Matching controls cannot exclude transient changes.

AP's unchanged strict graphics/Wi-Fi/touch/native-right-audio baseline collector
runs at620s, with the900s userspace fallback. All12 criteria expressions and
identity-only helper transformations must be verified. The provider result is
separate from this inherited baseline; neither closes a feature. Collect/review
both actual results before selecting another experiment. Do not re-arm AQ after
a failure. Capture outgoing AP state and late identity markers, but missing
pstore markers leave callback execution/persistence unresolved.

Deployment requires exact recovery/module/payload/runtime/build checks, the
live84,671 compiled-source/DT inputs checked against the frozen snapshot, actual
AP boot ID/release/cmdline, zero taint, touch ready, connected Wi-Fi and empty
pending selection. Run the real preboot guard under systemd without SUDO_UID.
Verify this current Happy session's native daemon-start continuation, preserve
all prequeue inputs atomically, and recheck the same identity and pending entry
immediately before reboot. Keep `spx-known-good` as the persistent default and
select AQ once. Existing authorization permits this experiment and possible
manual power-cycle risk; automatic EFI/early-kernel recovery remains unvalidated.
No live MSM component rebind or pinned audio unload/restart is permitted.

After a successful actual registration check, design a consumer trial against
the firmware supply order and standard shared regulator references. Rear-only
CCI/sensor identification may precede capture. Front/IR physical AVDD/DVDD,
CAMSS analog supplies, complete SID/binding scope and shutdown/stream semantics
remain prerequisites for their enabled candidates. No placeholders or guessed
RPMh camera votes. Final acceptance still needs the checklist's functional checks
on one converged candidate, including fitted accessories and physical stimuli.
