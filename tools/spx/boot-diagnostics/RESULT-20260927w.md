## Bounded silent PCM follow-up

At 885 seconds, a one-second stereo 48 kHz S16_LE digital-zero stream on
`hw:0,0` exited successfully. The 15-file test archive has SHA256 manifest
`b907ddaa6fa6611ed6d796285c417cb6931360a5effbaad0b56fb95f9ce492d1`.
Its kernel delta shows DSP buffer submissions and matching PA/RDAC start and
stop events, with zero new SoundWire FIFO errors or PA-gain failures. This
establishes software PCM transport through the current card, not audible
output.

The test also exposed a routing error: both codec instances reported
`device=1 hw_params active_ports=1` and both PA paths started. Sysfs still
showed only the left WSA `Attached`/1; the right WSA remained `UNATTACHED`/N/A.
The enumerated-mode transport predicate checks the stale internal
`slave->dev_num` but not `slave->status`. A distinct follow-up kernel should
exclude unattached codecs from stream configuration and skip their DAPM/mute
writes, while preserving the attached codec's behavior. Do not test nonzero
speaker audio with both instances routed as device 1.
